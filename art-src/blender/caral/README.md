# Caral — Blender source assets

The editable Blender project lives **in this repository** at `art-src/blender`.
The `.blend` sources are tracked with Git LFS; the renders, GLB exports, source manifest
and hashes live alongside them so provenance is reproducible.

## Asset manifest

`caral_asset_manifest.csv` is a copy of the Blender project's asset table. It records
footprints, heights, triangle counts and the confidence level (`documentado`, `blockout`,
etc.) for each building. `renders.json` references the relevant row through `sceneAssetId`
when the render focuses on a single documented asset.

## Game GLB export

The game-ready city is `caral_city_lod0.glb` / `caral_city_lod1.glb`, copied into
`src/assets/cities/`. The export manifest (`caral_city_game_manifest.csv`) records:

| LOD | Scale | Size X × Y × Z (game axes) | Tris | Parts | Materials | Bytes |
|---|---|---|---|---|---|---|
| LOD0 | 0.08 | 30.4 × 2.814 × 49.628 | 18,120 | 10 | 10 | 906,728 |
| LOD1 | 0.08 | 30.4 × 2.814 × 49.628 | 6,194 | 10 | 10 | 454,348 |

- Pivot: center of the footprint at ground level.
- Orientation: Y-up; the main stair faces +Z. The game manifest uses exported GLB axes
  (X width, Y height, Z depth); the source Blender scene is Z-up.
- The city is merged by material (10 draw calls), excludes terrain/trees/rocks/humans and
  includes the city props.
- The raw `caral_rts_kit.glb` (97 nodes/171 primitives) and `caral_pyramide_mayor.glb` are
  source assets, not game-scaled exports.

Preview the GLB in the browser without booting a match:

```bash
yarn dev
# http://localhost:5173/?city=caral
```

The showcase loads both LODs, fixes the missing `MAT-Sand_Desert` base colour in the viewer,
and exposes `window.__cityDemo` for inspection. The plaza stalls included in the export must
be reviewed against the campaign note that Caral has no attested market before using the
city in the campaign.

## Modular scenery

`caral_pyramid_mayor` is the first modular scenery asset. It isolates the Pyramid Mayor
(`GEO-Caral_PyramideMayor_LOD0`) and Plaza Mayor (`GEO-Caral_PlazaMayor_LOD0`) from
`scenes/caral_rts_kit.blend`; it excludes `PlazaCentral`, the market stalls and the terrain.

| LOD | Size X × Y × Z (game axes) | Tris | Draw calls | Materials | Bytes |
|---|---|---|---|---|---|
| LOD0 | 13.904 × 2.7744 × 15.5352 | 6,044 | 7 | 7 | 293,796 |
| LOD1 | 13.904 × 2.7744 × 15.529 | 2,408 | 7 | 7 | 154,020 |

- Pivot: footprint centre at ground level; foundations extend to -0.16.
- Orientation: Y-up; main stair +Z.
- Materials: Fire, Plaster Red/White/Yellow, Stone Dark/Granodiorite, Thatch.
- Source: `scenes/caral_rts_kit.blend`; build script:
  `scripts/blender/build_caral_scenery.py --asset=pyramid-mayor`.
- Preview: `yarn dev` → `http://localhost:5173/?scenery=caral`.
- Status: the Caral landmark on `m1_caral`; visual-only (no collision).

Rebuild:

```bash
blender --background art-src/blender/scenes/caral_rts_kit.blend \
  --python scripts/blender/build_caral_scenery.py -- \
  --asset=pyramid-mayor \
  --out-dir=art-src/blender/exports/caral \
  --game-dir=src/assets/scenery/caral \
  --blend=art-src/blender/scenes/caral_pyramid_mayor.blend
```

Review renders:

```bash
blender --background art-src/blender/scenes/caral_pyramid_mayor.blend \
  --python scripts/blender/render_caral_scenery.py -- --asset=pyramid-mayor
```

### Anfiteatro

`caral_anfiteatro` combines Templo Anfiteatro, Altar Circular and Templo Banqueta. The banqueta
is a detached small platform in the source layout; it is kept as part of the ceremonial
setpiece but can be split later.

| LOD | Size X × Y × Z (game axes) | Tris | Draw calls | Materials | Bytes |
|---|---|---|---|---|---|
| LOD0 | 19.704 × 1.016 × 7.2 | 3,520 | 7 | 7 | 170,580 |
| LOD1 | 19.704 × 1.016 × 7.2 | 1,403 | 7 | 7 | 84,880 |

- Pivot: footprint centre at ground level; foundations extend to -0.2.
- Orientation: Y-up; the source kit places the main approach toward +Z.
- Materials: Fire, Plaster Red/White/Yellow, Sand Desert, Stone Dark/Granodiorite.
- `MAT-Sand_Desert` is fixed at build time by removing the unsupported procedural Base Color
  link, so the GLB exports its `baseColorFactor`.
- Preview: `?scenery=caral-anfiteatro`.
- Status: secondary setpiece of the Caral landmark on `m1_caral`; visual-only.

Rebuild:

```bash
blender --background art-src/blender/scenes/caral_rts_kit.blend \
  --python scripts/blender/build_caral_scenery.py -- \
  --asset=anfiteatro \
  --out-dir=art-src/blender/exports/caral \
  --game-dir=src/assets/scenery/caral \
  --blend=art-src/blender/scenes/caral_anfiteatro.blend
```

Review renders:

```bash
blender --background art-src/blender/scenes/caral_anfiteatro.blend \
  --python scripts/blender/render_caral_scenery.py -- --asset=anfiteatro
```

### Upper-Half pyramids

The five remaining pyramids of Caral Alto are exported as separate modular assets. They use the
flat authored Upper-Half terrain instead of individual pads, and the procedural plan filters
their five rows while the GLBs load.

| Asset | Plan anchor | LOD0 size (game axes) | LOD0 tris | Draw calls | Bytes |
|---|---|---|---|---|---|
| `caral_pyramid_central` | `central` | 5.84 × 1.5792 × 8.2028 | 792 | 3 | 46,128 |
| `caral_pyramid_quarry` | `quarry` | 5.4904 × 1.2552 × 4.0008 | 792 | 3 | 46,132 |
| `caral_pyramid_lesser` | `lesser` | 4.2336 × 0.976 × 3.9295 | 792 | 4 | 46,776 |
| `caral_pyramid_gallery` | `gallery` | 5.9976 × 1.6632 × 6.1462 | 924 | 3 | 53,252 |
| `caral_pyramid_huanca` | `huanca` | 4.5648 × 1.2008 × 4.6995 | 792 | 4 | 46,780 |

Rebuild one with:

```bash
blender --background art-src/blender/scenes/caral_rts_kit.blend \
  --python scripts/blender/build_caral_scenery.py -- \
  --asset=central-pyramid
```

If any modular Upper-Half pyramid or the Anfiteatro fails to load, the game clears all modular
setpieces and rebuilds the procedural city from the same plan.

## Ingest

```bash
yarn art:blender
yarn art:validate
```

`yarn art:blender` verifies the source hashes, converts the PNGs to budgeted WebP, writes
`src/art/manifest.json` and `public/media/generated/PROVENANCE.md`, then validates the result.

## Adding a render

1. Render a new PNG into `art-src/blender/renders/` with a stable name.
2. Add an entry to `renders.json` with the source hash, camera, scene, sources and Spanish
   `alt`/`caption`.
3. Run `yarn art:blender --only=<id>` for a new render, or
   `yarn art:blender --only=<id> --force` when replacing an existing render.
4. Review the WebP and run `yarn art:review --id=<id> --reviewer=<name> --approve`.
